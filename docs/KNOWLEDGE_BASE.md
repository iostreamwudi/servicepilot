# ServicePilot 知识库说明

## 当前构建方式

知识种子保存在 `data/knowledge-seed.json`，服务启动后由 `/api/bootstrap` 幂等写入 `knowledge_documents` 表。重复初始化会按知识 ID 更新内容而不是重复插入；Docker 环境中的 D1 兼容数据库使用独立持久化卷，应用升级不会删除知识。

每条知识包含业务域、标题、版本、责任团队、正文、检索关键词、风险等级、是否转人工、发布状态、覆盖率、来源类型、来源标题和来源地址。`official` 表示从政府官网法规或政策中提炼的客服化摘要；`internal_demo` 表示为了演示产品流程而设计的商城 SOP，不代表任何真实企业制度。

## 来源与范围

当前项目文件中共有 1,533 条知识资料，覆盖退款/退货、商品破损、物流与改址、数电发票四个业务域及扩展审核语料。其中 25 条为可直接服务客服场景的结构化 `active` 规则；1,008 条来自政府官方文件的按条切片，以及 500 条生成式候选，统一处于 `review` 状态。

1,508 条 `review` 资料不会直接参与 Agent 自动回答；只有经过客服化改写、业务与合规复核的规则才允许进入 `active` 检索集合。这样可以保留法规与候选语料的审计依据，同时避免把未经审核的原文或模型生成内容直接当成客服口径。

知识正文为面向客服场景的摘要，不长篇复制原文；每条保留官方链接以供复核。规则入库不等于已经完成企业法务审批，生产使用前仍需业务负责人和合规人员双人确认。

## 检索与回答

Agent 先识别四类业务意图，再从该组织的 `active` 知识中按业务域过滤，使用问题与关键词的可解释匹配分数选择知识；没有明显长尾关键词时回退到该意图的核心知识。命中内容作为大模型唯一可信知识上下文，同时返回知识 ID、版本和来源。数据库不可用时仅使用四条最小安全规则，超出范围则转人工。

当前生产回答仍由关键词检索提供知识。另有不切流量的生产影子链路：从 D1 按租户、`qwen3.7-text-embedding` 模型和当前索引版本读取向量，融合关键词、向量、覆盖率与业务动作进行 Top-K 重排，并记录与现网来源的差异、分数、理由、耗时和失败码。候选变化可由授权质量角色标记为改善、退化、等价或无法判断；系统按业务类目和索引版本计算样本量、失败率、P95 与复核结果，并只读提示是否具备灰度设计证据。影子结果和门禁均不进入 Prompt、不改变回答、转人工或流量。

## 治理要求

- 新增知识默认应经过内容录入、来源校验、业务/合规复核、灰度发布和失效归档。
- 法规更新、来源链接失效或业务 SOP 变更时必须升级版本并保留审计记录。
- `coverage` 是当前演示评测的指标，不等同于生产命中率或法规准确率。
- 禁止采集私有客服记录或包含直接个人标识符的数据作为知识内容。
