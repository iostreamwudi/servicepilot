# ServicePilot 系统架构与企业化边界

## 1. 分层架构

### 渠道层

商城 App、网页、微信小程序、电话与企业 IM 通过统一会话网关接入。渠道层只处理身份、消息协议和展示差异，不承载业务判断。

### 产品服务层

- 会话服务：会话状态、人工接管、上下文摘要和消息顺序。当前已实现服务端持久化语义记忆：只保存脱敏后的活跃意图、必要槽位和短摘要，不把完整对话反复写入模型上下文；订单号等运行时事实必须经过独立验证后才能复用。
- 工单服务：优先级、SLA、分配、审批、升级、关闭和重开。
- 知识服务：版本、有效期、责任人、权限、冲突和引用。
- 质检服务：抽样、评分、人工复核、申诉和失败归因；影子候选变化由授权质量角色复核并保留审计。
- 策略服务：路由、阈值、兜底、灰度、审批和回滚。
- 审计服务：记录用户、Agent和系统的关键动作。

### AI 编排层

意图识别 → 风险分类 → 混合检索 → 工具决策 → 统一证据包 → 回复生成 → 声明级审查 → 人工接管。Step 9.8 实验链路由有界状态机治理，限制总步骤、模型调用、工具调用和总耗时；预算耗尽或状态非法时安全拒答或转人工。

模型不直接访问生产系统。所有工具调用都经过白名单、参数校验、权限判断、超时和审计；当前只开放退款状态只读查询，缺少已验证订单号时先请求补充信息，不允许模型猜测实时状态。

### 数据层

- D1：组织、成员、会话、消息、工单、知识元数据、质检、策略和审计。
- R2（下一阶段）：知识文件、导入原件、导出报告和附件。
- D1 版本化向量索引：按租户、Embedding 模型和当前版本指针读取；普通生产仍只用于影子召回。显式 Step 9.8 V2 实验可执行 RetrievalScope → BM25/Dense 宽召回 → RRF → 受限业务 Boost → 语义 Reranker，并保留分阶段 Trace。
- D1 影子复核：按影子运行唯一保存改善、退化、等价或无法判断结论；统计按租户、索引版本和业务类目隔离。
- 模型网关：当前回答模型为 `minimax-m3`，通过火山方舟 Agent Plan OpenAI 兼容接口调用；向量索引继续使用独立 Embedding 模型。网关统一处理模型标识、超时、降级和调用审计。

## 2. 租户与权限

所有业务记录包含 organizationId，任何查询和写入都必须绑定当前成员所属组织。当前演示空间采用单租户种子数据；生产阶段应在服务端完成成员关系查询，不能信任客户端传入的 organizationId 或 role。

角色权限采用 RBAC，针对退款、赔付、知识发布、策略发布和数据导出增加基于资源与风险的二次判断。身份验证不等于业务授权。

## 3. 写操作安全

- 输入验证：限制长度、枚举值和关联资源。
- 幂等：创建退款、工单和外部通知必须携带幂等键。
- 审批：高风险操作需要至少一名授权人员确认。
- 审计：记录操作者、动作、资源、结果、风险与最少必要上下文。
- 脱敏：日志和模型上下文中不保存完整手机号、证件号和支付信息。
- 最小权限：Agent只获得当前任务需要的工具与数据范围。

## 4. 可用性和降级

- 模型网关支持主备模型、超时、重试和熔断。
- 实验 Agent 链路最多执行 7 个状态步骤、1 次模型调用、1 次工具调用和 25 秒；迟到结果不得重新进入已结束状态。
- 订单工具失败时不允许模型猜测结果。
- 生成回答必须接受声明级审查：实时状态需要工具证据，数字与时效需要知识证据，未授权执行和确定性承诺必须改写或安全降级。
- 知识服务不可用时只返回稳定标准话术或转人工。
- 质检异步执行，不阻塞客服主链路。
- 影子检索通过 Worker `waitUntil` 后台保活，5 秒超时或索引/写入失败只记录失败，不阻塞回答、转人工或 Prompt 链路。
- Step 9.8 V2 的 Dense 失败降级为可信 BM25-only；Reranker 失败严格回退 RRF+Boost；两路均无可信候选时澄清或转人工，禁止默认知识强答。V2只由显式实验头进入，不替换V1或普通生产。
- 灰度证据门禁只读计算样本量、类目覆盖、失败率、P95、改善率和退化率；展示筛选不改变统计 cohort，门禁不得自动修改流量。
- 会话记忆读写失败时降级为无状态问答，不阻塞客服主链路；历史状态只用于理解“那要多久”等指代，不可充当订单或政策事实。
- 高峰期优先保障意图识别、订单查询和人工接管，暂停非核心总结与改写。

## 5. 当前已实现与待实现

已实现：产品信息架构、交互演示、D1 关系模型、数据库迁移、身份感知初始化、工单读取/创建接口、Agent 回答接口、服务端持久化语义会话记忆、上下文感知的混合意图检索、可解释召回信号、可配置风险转人工、GLM-5.2 模型网关安全降级、只读订单退款工具、工具决策审计、统一知识/工具证据包、声明级回答审查、Step 9.8 有界 Agent 状态机、100条真实与安全组合冻结评测集、真实模型回归评测，以及版本化向量索引、动作重排 Hybrid 的生产影子运行、质量角色复核、审计和只读灰度证据门禁。Step 9.8 Phase 1 V2 已在隔离实验分支实现 RetrievalScope、BM25/Dense宽召回、RRF、受限Boost、供应商无关Reranker与安全回退；本地BM25-only诊断低于V1，尚未接管生产回答。

已完成真实Retrieval验证：腾讯云live D1的25条active知识与当前25条向量双向一致；真实Dense与`qwen3-rerank`在回归集和独立新增集均完成0 fallback运行。Dense有召回价值，但Hybrid-before未超过V1，Reranker使Recall@5从96.81%/96.47%降至84.04%/88.24%，因此V2未通过晋级门禁并继续隔离。

待实现：冻结新的Reranker任务说明/融合策略与多相关性Golden Set后，才可用另一批独立数据复验；用独立新增数据验证证据包与有界状态机的泛化能力；在隔离沙箱补足包含有效订单号、工具超时和迟到返回的真实工具场景。企业化能力仍需补齐完整 RBAC 中间件、文件存储、消息队列、自动运行评测、监控告警和生产灾备。当前知识域只有4个，生产回答仍采用稳定的 Step 9.1 路径；Step 9.7 与 Step 9.8 在同一冻结集上均为 83/100，只证明治理机制未破坏基线，不宣称效果提升。
