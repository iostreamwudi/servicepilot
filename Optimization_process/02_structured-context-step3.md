# Step 3｜结构化多轮上下文

## 1. 方案

在 Agent 路由前，将最近用户消息提取为结构化会话状态：

- 当前业务主题：退款、破损售后、地址、发票。
- 主题证据：触发主题判断的词或短语。
- 已提供事实：例如订单号。
- 当前待解决问题：例如“什么时候能好”。
- 主题置信度：用于防止低置信度历史污染当前路由。

该状态只作为上下文理解依据，不能直接当作业务事实；业务事实仍必须来自生效知识或只读工具。

## 2. 实际改动

- `lib/intent-router.ts`
  - 新增 `ConversationContext` 和 `extractConversationContext`。
  - 支持间接表达：例如“原E卡”“支付银行卡”“公司名称/税号”。
  - 对省略式追问增加“什么时候”等 follow-up 识别。
  - 结构化主题置信度足够时，避免通用向量结果覆盖已确认的会话主题。
  - 路由结果增加 `conversationContext`，便于追踪。
- `app/api/agent/respond/route.ts`
  - 将结构化上下文写入长期会话状态摘要。
  - 将结构化上下文传给模型网关，帮助模型理解指代和当前待解决问题。
  - 保留原有安全拦截、知识生效状态和订单工具白名单。
- `tests/intent-router.test.mjs`
  - 新增发票和退款间接表达的多轮测试。
  - 新增结构化上下文可审计字段测试。

## 3. 验证结果

- 自动化测试：23/23 通过。
- 本地 85 条 CSDS 真实路由集预检查：
  - 路由+转人工联合通过率：57/85（67.1%）。
  - 知识来源准确率：68.2%。
  - 转人工准确率：90.6%。
  - 12 条用例使用了历史/结构化上下文路由。
- 该预检查只验证本地路由，不等同于腾讯云上的完整 qwen-plus 端到端评测；需要部署后用相同 100 条评测集复跑。
